# 盲扫定位指南（现场操作手册）

> 面向"人到现场、没有网络、没有电脑"的用法：用这块板子扫一轮，把附近的 BLE 设备
> 记进 flash，回来插 USB 读出来。目标是**找出固定安装的设备**（考勤机、门禁读头、
> 打卡点、信标），而不是记录路人甲的手机。
>
> 参数、判据、概率都来自实测（`feat/usb-console` 分支 47df8d5 之后的固件）。

---

## 1. 出发前（5 分钟）

### 1.1 硬件

- 板子 + **能传数据的 USB 线**（纯充电线读不出记录）+ 充电宝（CR2032 带不动，峰值 350–420 mA）。
- LED：单色灯，靠闪法区分状态（见 §5）。

### 1.2 配置检查（插一次电脑，或连一次 AP）

```powershell
python tools/usb_cli.py -p COM7 status
```

要看到这四项：

| 字段 | 期望 | 说明 |
|---|---|---|
| `scan_filter` | `true` | 丢掉手机/手表/耳机/Windows 电脑 |
| `scan_full_duty` | `true` | 没有 Wi-Fi 客户端时 **100% 全时监听** |
| `scan_clear_rounds` | `true` | 每次窗口从空表开始，`packets` 才是单窗真值 |
| `scan_duration_s` | `120` | 单次窗口长度 |

不对就用命令台改（参数不需要网络）：

```
filter on
timing 300 60 120        # itvl 300ms / win 60ms（有 full_duty 时实际是 300/300 = 100%）/ 窗口 120 秒
```

### 1.3 清空归档

```powershell
python tools/usb_cli.py -p COM7 records clear
```

归档只有 **128 条**，不清的话上一次的数据会被覆盖。收藏夹（`pins`）不受影响。

## 2. 现场三种任务

### A. 基线采集（"这个房间有什么固定设备"）

1. 板子放在你想记录的**中心位置**（桌面、柜顶都行，别塞进金属抽屉）。
2. **双击 BOOT** → LED 变**连续快闪**（5 Hz）= 正在扫。
3. **不动，等 120 秒**（快闪停 = 窗口结束、正在写 flash）。
4. 快闪停下后再等 **2–3 秒**，然后断电/拔线，走人。

### B. 定位扫描（"从电梯口走到工位，一路找"）

1. 出电梯就**双击**开始。
2. 正常步速走（≤1.3 m/s，别跑），**每个可疑点停 10–15 秒**：
   电梯口、闸机、门禁面板、墙上插座/USB 小盒子旁、考勤机前面。
3. 走到 120 秒窗口结束（快闪停）→ 再等 2–3 秒 → 拔线。

> 为什么必须停：抓取概率 = 1 − (1 − 占空比)^(停留时间 / 广播间隔)。
> 100% 占空比下，"走过去 12 秒"对 200 ms 的信标≈100%，对 5 秒的信标才 91%；
> 停下来 10 秒就都是"必中"。

### C. 逼近确认（"就是这台，确认一下"）

1. 站到设备 **0.5 m 内**。
2. 命令台临时缩短窗口（省时间）：`timing 300 60 20`（20 秒）。
3. 双击扫一轮，读 `records` —— 目标应该是 **-40 ~ -55 dBm**，`packets` 一大把。
4. 恢复：`timing 300 60 120`。

## 3. 判读规则（照着顺序筛）

### 第 1 步：丢掉"擦边"数据

看 `packets`。120 秒窗口、100% 占空比下：

```
packets >= 50     → 整窗在线，可信
packets 6 ~ 50    → 半程在范围内，可信但注意 RSSI
packets <= 3      → 路过/擦边，不要用来下结论
```

间隔反推（**只在这个前提下成立**：每窗清表 + 100% 占空比）：

```
T ≈ 窗口秒数 / packets        例：120 s / 562 包 ≈ 213 ms
```

### 第 2 步：优先看公网地址

`addr_type = 0`（pub）= **MAC 固定**，一定是固定安装的设备。
随机地址（rnd）绝大多数是手机/耳机（会轮换），但也可能是"随机静态"（我们见过一台 12 轮都在的 Apple 设备），所以随机地址不能一律丢，只是优先级低。

### 第 3 步：用 RSSI 分层

| RSSI | 距离感 |
|---|---|
| -40 ~ -55 | 就在眼前（1 m 内） |
| -55 ~ -70 | 同一个房间 |
| -70 ~ -85 | 隔一堵墙 |
| -85 ~ -100 | 远处/隔两堵墙 |

### 第 4 步：看厂商与服务

| 特征 | 结论 |
|---|---|
| `mfg_company = 0x0100` | 钉钉蓝牙打卡点（TomTom ID） |
| `svc = 0xFE3C` 或名字含 `RTK_BT` | 钉钉打卡点 |
| `0x0E25` / `0x0124` / `0x0C64` / `0x0199` | 海康 / HID / dormakaba / SALTO（门禁系） |
| `0x004C` + 子类型 `0x02` + 26 字节 | iBeacon（真信标） |
| `0xFCB2` | Location Enabled Adv（定位类） |
| `0xFE95` | 小米 MiBeacon（门磁/温湿度/人体感应） |
| 无厂商 ID、只有服务 UUID、载荷极简、周期固定 | **最像"固定终端/信标"** |

### 第 5 步：交叉验证（最强）

- **遮挡法**：用金属盒/几层锡箔纸把疑似设备包住，再扫一轮 → **哪个地址消失就是它**。
- **移动法**：拿着板子远离 20 m 再扫 → 哪个 RSSI 掉得最快就是它。
- **两趟对比**：同位置扫两次，两次都在（且 `packets` 都很高）的 = 固定设备。

## 4. 读数据（回到办公室）

最快：

```powershell
python tools/usb_cli.py -p COM7 records > recs.jsonl     # 每行一条 JSON
python tools/usb_cli.py -p COM7 pins                     # 收藏夹（不会被扫描覆盖）
python tools/usb_cli.py -p COM7 pin 3                    # 把 records 第 4 行收藏起来
```

不依赖固件（板子还能枚举串口就行）：

```powershell
python -m esptool --chip esp32c6 -p COM7 read-flash 0x320000 0xD0000 storage.bin
python bgw_usb_dump.py storage.bin        # 按 168 B 记录 + magic 搜出来
```

每条记录里有：`addr / addr_type / adv_type / name / raw(31B) / rsp(31B) /
mfg_company / mfg / mfg_src / svc / uuid / major / minor / rssi / rssi_max /
rssi_avg / packets / itvl_ms / dwell_ms / boot_seq / uptime_s`。

## 5. LED 与按键速查

| LED | 含义 |
|---|---|
| **连续快闪（5 Hz）** | 正在扫（窗口进行中） |
| 每 3 秒闪一次 | 空闲、射频关闭（有配置） |
| 常亮 | 空闲，但**没有任何配置** |
| 1 Hz 慢闪 | 正在广播（克隆中） |
| 六连快闪 | 射频错误 / 正按住按钮即将恢复出厂 |

| 按键 | 动作 |
|---|---|
| 单击 | 克隆 开 / 关 |
| **双击** | **盲扫：开一个窗口（默认 120 秒），结束后自动落盘** |
| 三击 | 停射频（窗口中途三击 = 提前结束，**也会落盘**） |
| 按住 5 秒 | 警告（六连快闪），松手取消 |
| 按住 8 秒 | 恢复出厂（配置清空） |

## 6. 坑清单（都是踩过的）

1. **窗口结束那 1–3 秒别断电** —— 正在写 flash。写坏了归档，固件不会自动格式化（数据只此一份），只能 `records format` 或 esptool 抠原始字节。
2. **中途三击**现在也会落盘（早期版本会白扫一趟），但窗口没走完就少了后半段数据。
3. **别用日志里的 `itvl_ms` 判断广播间隔** —— 它是到达间隔的 EMA，会被 3 个信道的毫秒级间隔带偏（实测差 5–20 倍）。用 `窗口秒数 / packets`。
4. **`packets` 是单窗值**（`clear_each_round` 开着）。关掉这个选项它就变累计，反推公式失效。
5. **手机/耳机换了 MAC 就是"新设备"** —— 所以只有公网地址能跨轮对比。
6. **有人连着板子的 AP 时占空比会回落到 50%** —— 盲扫时别用手机连它。
7. **纯 Classic 蓝牙 / 纯网络（TCP-IP）的考勤机，这块板永远扫不到**（C6 没有 BR/EDR 硬件）。遇到了要换工具：Android 的经典蓝牙扫描 App，或 Windows 的"添加蓝牙设备"列表。
8. 归档 **128 条 = 一个满窗口的量**，第二个窗口会开始覆盖第一个。**扫完就读、读完就清**。

## 7. 实测参考值（判断"数据是否正常"）

| 场景 | 100% 占空比、120 秒窗口 |
|---|---|
| 安静办公室（默认 filter on） | 5 台左右，`packets` 500–1500，过滤掉 74% 的帧 |
| 白天人多（filter on） | 10–30 台；关掉 filter 会到 128（表满） |
| 收包速率 | ~147 包/秒（20% 占空比时只有 ~7.5 包/秒） |
| 固定信标实测间隔 | 80–210 ms（不是 iBeacon 那种 1–5 秒） |

如果 `records` 只有 0–1 台、且 RSSI 全在 -90 以下 → 大概率**那里没有 BLE 源**，不是"没扫到"。

```
出发前   records clear / 确认 filter=on full_duty=on duration=120
现场     双击 → 走 + 在每个可疑点停 10–15 秒 → 快闪停 → 再等 3 秒 → 拔线
判读     packets>=50 才算数；先看 pub 地址；RSSI 分层；T = 窗口/packets

```
